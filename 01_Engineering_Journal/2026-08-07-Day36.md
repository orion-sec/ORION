# ORION Engineering Journal — Day 36

**Date:** 07 August 2026  
**Focus:** Live Microsoft Entra Sign-In Evidence and Security Reasoning Integration

---

## 1. Objective

The objective for Day 36 was to move ORION beyond simply collecting Microsoft Entra sign-in telemetry.

The goal was to establish an end-to-end investigation path where live Entra sign-in events could:

1. Be collected from Microsoft.
2. Be converted into ORION's internal evidence model.
3. Be attached to the Investigation aggregate.
4. Pass through the evidence reasoning layer.
5. Generate structured security findings.
6. Remain available for later correlation, confidence assessment, and investigation decisions.

This represents another step toward ORION operating as an investigation system rather than a collection of independent security scripts.

---

## 2. Architecture Implemented

The Day 36 investigation path is now:

        ↓

        ↓

        ↓

The important architectural principle is separation of responsibilities.

Providers collect telemetry.

Factories normalize external data.

Models represent internal security evidence.

Reasoners interpret evidence.

The pipeline orchestrates the investigation.

The Investigation object maintains the accumulated investigation state.

## 3. Sign-In Evidence Model

A dedicated SignInEvidence model is now used to represent Microsoft Entra authentication telemetry inside ORION.

The model allows authentication evidence to be handled independently of the original Microsoft API response.

Examples of captured context include:

- User
- User ID
- IP address
- Application
- Authentication result
- Client application
- User agent
- Conditional Access status
- Microsoft Entra risk level
- Location
- Device information
- Correlation ID

This creates a normalized internal representation that future providers can potentially map into.

## 5. Investigation Aggregate Integration

The Investigation model was extended to maintain authentication evidence using:

sign_in evidence → Investigation.signin_evidence

The pipeline aggregate builder was updated so collected sign-in evidence becomes part of the central Investigation object.

This is important because later investigation stages no longer need to query Microsoft directly.

They can reason over the investigation state maintained by ORION.

---

## 6. Sign-In Reasoner

A dedicated sign-in reasoner was introduced.

The reasoner evaluates SignInEvidence and produces structured Finding objects.

Current reasoning capabilities include evaluation of:

- Authentication failures
- Microsoft Entra identity risk
- Conditional Access enforcement
- Managed/unmanaged device state
- Device compliance state

Example generated finding:

[Conditional Access]
Conditional Access was not applied to the sign-in.

The reasoner therefore converts raw authentication telemetry into analyst-readable security observations.

---

## 7. Unified Evidence Reasoning

The existing evidence reasoning layer previously handled dictionary-based evidence such as infrastructure and network observations.

Day 36 extended this architecture so it can also reason over typed SignInEvidence objects.

The reasoning layer now supports both:

- Existing dictionary-based evidence
- Structured SignInEvidence objects

This was implemented without removing the existing Infrastructure and Network reasoning routes.

This preserves backward compatibility while allowing ORION's evidence architecture to evolve toward strongly typed security models.

## 10. Important Security Reasoning Observation

A key lesson from today's implementation is that:

"Conditional Access was not applied"

is a security observation, but it is not automatically proof of malicious activity.

ORION must therefore distinguish between:

Evidence
Findings
Correlated signals
Risk
Confidence
Verdict

For example, a sign-in without Conditional Access may be benign.

However, the same observation combined with:

- High-risk IP intelligence
- Impossible travel
- Unmanaged device
- Non-compliant device
- High Entra risk
- Abnormal user behaviour

could materially increase investigation confidence.

This reinforces the need for multi-signal correlation rather than single-indicator verdicts.
