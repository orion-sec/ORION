# ORION Engineering Journal — Day 40
**Date:** 11 August 2026

## Objective

Validate ORION's investigation expansion architecture against live Microsoft Sentinel incidents and extend the investigation pipeline so environment evidence contributes to investigation scope and blast-radius assessment.

## Work Completed

### 1. Investigation Expansion Engine

Created:

`11_Modules/correlation/investigation_expander.py`

Implemented logic to transform environment-search evidence into a normalized investigation scope.

Supported entity categories:

- Users
- IP addresses
- Devices
- File hashes
- Domains
- URLs

The expansion layer deduplicates related entities and calculates the number of affected entities discovered outside the original alert context.

---

### 2. Investigation Expansion Pipeline Stage

Added:

`investigation_expansion_stage`

Pipeline sequence now includes:

Entity Correlation
→ Environment Search
→ Investigation Expansion
→ Blast Radius
→ Evidence Reasoning

This allows ORION to move from simply finding related telemetry to understanding the wider investigation scope.

---

### 3. Blast Radius Assessment

Created:

`11_Modules/correlation/blast_radius.py`

The blast-radius engine evaluates:

- Whether investigation expansion occurred
- Number of affected entities
- Active entity categories
- Entity counts
- Investigation scope

Example classifications include:

- No Expansion
- Single-Entity
- Multi-Entity

This provides a deterministic representation of how far activity has spread across the environment.

`correlation/entity_correlator.py`

## Engineering Observation

The live malware investigation exposed the next major capability gap.

ORION correctly asks questions such as:

- Is the detected hash malicious?
- What is the reputation of the file?
- Is the domain malicious?
- Is the URL suspicious?

However, ORION currently lacks an external reputation source capable of answering these questions automatically.

## Day 41 Direction

Integrate VirusTotal as ORION's first external threat-intelligence enrichment provider.

Initial targets:

- SHA256 / file hashes
- Domains
- URLs
- IP addresses

The objective is for ORION to enrich extracted IOCs automatically and provide the results directly to the investigation reasoning engine without requiring the analyst to manually pivot to VirusTotal.

Future enrichment providers can include:

- AbuseIPDB
- Microsoft Defender
- CrowdStrike
- Additional commercial threat-intelligence platforms
