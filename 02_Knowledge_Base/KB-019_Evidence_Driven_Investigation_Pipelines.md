# Evidence-Driven Investigation Pipelines

## Overview

Traditional investigation scripts often perform isolated tasks and immediately print results.

Enterprise investigation platforms instead use a staged processing pipeline where every stage contributes evidence that subsequent stages consume.

---

# ORION Pipeline Architecture

Current ORION investigation flow:

```
Investigation
        │
        ▼
IOC Extraction
        │
        ▼
Identity Extraction
        │
        ▼
Identity Enrichment
        │
        ▼
Business Impact
        │
        ▼
IP Enrichment
        │
        ▼
Threat Intelligence
        │
        ▼
Threat Correlation
        │
        ▼
Contextual Risk
```

Each stage enriches the investigation with additional structured evidence.

---

# Threat Intelligence

Purpose:

Determine whether extracted indicators have known malicious history.

Produces:

- reputation
- confidence
- intelligence source
- report count
- availability

Threat Intelligence enriches evidence but does not make decisions.

---

# Threat Correlation

Purpose:

Combine intelligence collected from one or more threat intelligence sources into a single assessment.

Produces:

- overall verdict
- confidence
- supporting reasoning
- contributing sources

Correlation reduces multiple intelligence observations into a single analytical conclusion.

---

# Contextual Risk

Purpose:

Evaluate the overall investigation risk.

Current implementation analyses the investigation narrative.

Future implementation will instead consume evidence generated by previous pipeline stages.

Future inputs will include:

- Threat Correlation
- Business Impact
- Identity Context
- IP Context
- MITRE ATT&CK
- Behaviour Analysis
- Detection Confidence

This evolution moves ORION from text analysis toward evidence-based reasoning.

---

# Why Pipeline Stages Matter

Independent scripts duplicate work.

Pipeline stages encourage:

- reusable outputs
- modular engineering
- dependency management
- simpler testing
- easier debugging
- future scalability

Every stage should have one clearly defined responsibility and expose structured outputs for downstream stages.

---

# Architectural Evolution

Stage 1:

```
Investigation
↓

IOC Extraction
```

Stage 2:

```
Investigation
↓

Evidence Collection
↓

Evidence Enrichment
↓

Threat Intelligence
↓

Threat Correlation
↓

Risk Assessment
```

The second model better reflects enterprise SOC investigation platforms because decisions are built upon accumulated evidence rather than isolated observations.
