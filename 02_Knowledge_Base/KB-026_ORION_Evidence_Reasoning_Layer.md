# KB-026 – ORION Evidence Reasoning Layer

## Principle

Separate observed evidence from interpreted findings.

Evidence and findings represent two different concepts within ORION.

---

## Evidence

Evidence represents facts collected from external sources.

Example:

{
    "category": "Infrastructure",
    "statement": "Infrastructure usage type is Data Center/Web Hosting/Transit."
}

Evidence should never represent interpretation.

---

## Findings

Findings represent ORION's interpretation of collected evidence.

Example:

{
    "category": "Infrastructure",
    "finding": "The investigated IP appears to originate from hosted or data-centre infrastructure."
}

Findings should always be generated by ORION rather than copied directly from external providers.

---

## Evidence Reasoning Layer

The Evidence Reasoning Layer sits between Evidence Collection and Threat Correlation.

Architecture:

Threat Results

↓

Evidence Collection

↓

Evidence Reasoning

↓

Threat Correlation

↓

Operational Decision

This architecture separates data collection from interpretation.

---

## Standardized Finding Creation

Finding objects should be created using:

create_finding(category, finding)

located in:

11_Modules/evidence_reasoning.py

This provides a single standardized method for constructing Finding objects.

---

## Current Reasoning Capability

Current implementation includes:

- Infrastructure reasoning

Future reasoning categories may include:

- Network
- Reputation
- Historical
- Identity
- Behaviour
- Attack
- Business Context

---

## Engineering Principle

ORION should never make operational decisions directly from raw evidence.

Evidence should first be interpreted into findings before contributing to higher-level threat correlation and decision making.

This layered architecture improves extensibility, readability, and long-term maintainability.
